1

Export AOI Imagery 01_gee_export.py

Uses Google Earth Engine to export a 6-band GeoTIFF over the Anantapur AOI (14.62°N – 14.76°N, 77.54°E – 77.68°E). Each band is derived from a separate, physically distinct data source to avoid band redundancy. The GeoTIFF's own geotransform provides coordinates for every pixel — no separate coordinate export needed.

📥 AOI bounding box 📥 GEE authenticated account 📤 aoi_export.tif (6-band, 30m)
2

Extract Labeled Patches 02_extract_labeled_patches.py

Pairs the exported GeoTIFF with real ground-truth well data. For each labeled point (lat/lon/label from the SOI Wells dataset), the script cuts a 65×65 pixel patch centered on that location. Patches falling outside the AOI or containing no-data pixels are automatically skipped.

The dataset contains 1,112 labeled points: 278 positive (known suitable/productive wells from SOI data) and 834 negative (randomly sampled locations with a 330m spatial buffer from positive wells, 1:3 ratio).

📥 aoi_export.tif 📥 labels.csv (SOI Wells) 📤 labeled_patches.npz
3

Tile Deploy Grid 03_tile_deploy_grid.py

Cuts the full AOI GeoTIFF into a non-overlapping grid of 65×65 patches covering the entire area. Each patch gets a real lat/lon center coordinate. This is the dataset that gets run through the trained model to "paint" the full suitability map — separate from labeled patches (which are only for training/evaluation).

Produces 484 geocoded grid cells spanning the full AOI.

📥 aoi_export.tif 📤 deploy_grid.npz (484 patches)
4

Train Hybrid Model 04_train_hybrid_model.py

Trains the ResNet18 + XGBoost hybrid on the labeled patches. The ResNet18 backbone has its first convolution adapted for 6 input channels (weights initialized via channel-averaged ImageNet pretrained weights). It is fine-tuned end-to-end for 8 epochs as a pretext binary classifier, then switched to embedding mode to extract 512-dimensional feature vectors.

These embeddings are concatenated with 12 tabular features (per-band mean and std) to form a 524-dimensional input for XGBoost (300 trees, max_depth=5). The train/test split uses a genuine geographic block hold-out via K-Means spatial clustering — not random shuffling — to avoid spatial leakage.

📥 labeled_patches.npz 📤 geo_resnet.pth 📤 xgboost_model.json
5

Run Inference 05_run_inference.py

Loads the trained CNN and XGBoost model and runs them over all 484 deploy grid cells. For each cell, it extracts the 512-d CNN embedding, appends 12 tabular features, and gets the XGBoost probability of suitability. The output is a GeoJSON file with one Point feature per grid cell, each carrying a suitability_probability property.

📥 deploy_grid.npz 📥 saved_model/ 📤 suitability.geojson (484 features)
6

Backend & Frontend app.py + index.html

A FastAPI backend serves the pre-computed suitability.geojson via a REST endpoint (/api/suitability). The frontend fetches this data and renders an interactive Leaflet heatmap with a blurred/hazy overlay, color gradient (sand → deep blue), opacity control, and geocoder search. Each grid cell is clickable for its exact suitability percentage.

📥 suitability.geojson 📤 Interactive map at localhost:8000

🔬 Why Geographic Block Hold-Out?

Standard random train/test splits in geospatial data lead to spatial leakage — a training point and a test point can sit meters apart, inflating accuracy estimates. Our pipeline uses K-Means clustering on the actual lat/lon coordinates to group labeled points into 6 geographic blocks, then holds out an entire block for testing. This gives an honest measure of how the model generalizes to genuinely unseen terrain, not just unseen rows in a shuffled table.
